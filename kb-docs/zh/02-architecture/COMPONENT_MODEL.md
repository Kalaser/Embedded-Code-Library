# 组件化与依赖管理

## 组件的定义

组件是具有明确职责、公开接口、构建规则、配置项和依赖声明的可复用代码单元。仅仅把文件放进一个目录，不代表已经形成组件。

## 推荐结构

```text
components/<component>/
├── include/<component>/      # 公共接口
├── src/                      # 私有实现
├── config/                   # 默认配置或模板
├── tests/                    # 单元/集成测试
├── CMakeLists.txt            # 构建描述
├── component.yml/json        # 可选元数据
└── README.md                 # 用途、API、依赖和移植说明
```

## 组件边界

- 公共头文件只暴露调用者需要的类型和函数。
- 私有实现不成为外部依赖。
- 依赖应显式声明，避免通过全局 include path 暗中耦合。
- 组件不能自行创建未声明的全局线程或定时器。
- 配置项应有默认值、有效范围和资源代价说明。
- 组件应说明是否线程安全、是否可从 ISR 调用、是否动态分配内存。

## 平台差异处理

优先顺序：标准库/标准接口 → 框架原生组件接口 → 项目平台适配接口 → 特定平台实现。不要为了形式统一，把不同平台的语义差异全部隐藏掉。

## 版本管理

产品集成要锁定组件 release/commit；记录本地 patch；升级前检查 API、配置、内存和线程语义变化；第三方组件必须保留许可证及 NOTICE。
