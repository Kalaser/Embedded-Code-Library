# 开源工程源码评估清单

## 项目成熟度

- [ ] 官方组织或可信维护团队拥有该仓库。
- [ ] README 说明项目定位、支持平台和构建方式。
- [ ] 有版本发布、变更日志或稳定 tag。
- [ ] CI 能覆盖主要构建目标。
- [ ] Issue/PR 有维护响应。
- [ ] 文档与当前源码版本一致。

## 工程架构

- [ ] 目录按职责划分，不只是按文件类型堆放。
- [ ] BSP、Driver、Middleware、Application 边界清楚。
- [ ] 构建依赖显式声明。
- [ ] 平台适配层与核心逻辑分离。
- [ ] 配置项有默认值、依赖和说明。
- [ ] 有独立测试或示例。

## 嵌入式适用性

- [ ] RAM/Flash/栈/堆开销可评估。
- [ ] ISR 使用规则清晰。
- [ ] 并发和线程安全契约明确。
- [ ] DMA/cache/对齐要求有说明。
- [ ] 失败与资源不足路径有处理。
- [ ] 有端口移植说明。

## 许可与供应链

- [ ] License 文件明确。
- [ ] submodule 和 bundled dependency 已识别。
- [ ] 许可证、NOTICE 和版权声明保留。
- [ ] release/commit 固定。
- [ ] 安全公告与 CVE 有跟踪机制。

## 复用结论

评估结果必须标记为以下之一：

- `ADOPT`：可按既定版本集成。
- `ADAPT`：需要适配层或裁剪后集成。
- `REFERENCE_ONLY`：仅借鉴架构，不直接引入代码。
- `REJECT`：许可证、维护、资源或技术风险不可接受。
